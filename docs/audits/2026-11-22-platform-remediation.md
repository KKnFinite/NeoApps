# NeoApps platform remediation, November 22, 2026

Issue #29. Production comparison commit `e40ce416a3844d2098867c7ab4e6917ed155bebc`, Render `dep-dc16p8u1egvs73815ba0`. The November 21 audit supplies the billing and production route samples. The comparisons below use synthetic operations on the release baseline and candidate. The release SHA, deployment and subsequent production observations belong in the issue timeline.

## What drives the bill

The November audit measured 450.10 active Neon hours, 114.28 CU-hours, 91.27 GB transferred and $10.53 accrued. A six-hour off-day sample had 24 compute starts and 301.9 active minutes. These figures establish the cost of keeping the database awake across the application. They do not assign individual wake-ups to jobs.

Render reported 627,711 requests and 30,343.79 MB for the audited period. The billing breakdown was 21.54 GB service-initiated and 8.45 GB HTTP bandwidth. The larger service-initiated category still lacks a verified per-destination breakdown. Reducing browser HTML reaches only part of that bill. The five-minute route sample identified Fuel Dispatch live panels (3,983,010 bytes across 30 responses) and DUCC (2,631,195 bytes across seven) as the largest browser response families. Of 92 sampled HTTP 304s, 90 were static. A separate one-hour sample attributed 150 of 159 rate-limit responses to Driver Routing state. These are samples, not monthly per-route totals. CPU p95 was 0.0515 of 0.5 CPU and memory p95 was 373 MB of 512 MB. Keep Starter.

## Regression disposition

The old and new NeoSektor route suites reported the same 59 failing assertion entries. The Ermac read-budget suite reported the same ten. Examples include superseded dashboard expectations and a SQL test recorder that counts a nested vendor subquery as a separate boundary lookup. Independent statement counts above include the complete SQL statements. The broader DUCC suite reproduced three pre-existing failures on both revisions, including legacy Outbound markup and physical/weather update expectations. One Sektor PostgreSQL reader test reproduced the same unchanged-revision assertion on both revisions. Four of 65 existing JavaScript assertions failed on both revisions, three in the older cadence harness and one in Dispatch. These failures remain open. No release tests were relaxed. The pre-existing stale shared-shell CSS revision was corrected to match the deployed asset contents.

Release-specific checks passed for the PostgreSQL revalidation and access boundary (4 tests), scoped authorization, restricted account types and password recovery (18 tests), and native ULD/Dispatch/DUCC PostgreSQL coverage (20 tests). The primary route and security-header selection passed 38 tests. Chromium and WebKit each exercised same-profile Driver Routing contention and Sort end, and compared the 56 DUCC controls after saving. The signed-in cross-node physical-window and Raiden browser selection passed all three tests and 26 subtests. The Dispatch bandwidth suite passed ten Python/PostgreSQL tests, six JavaScript tests, and an authenticated Chromium refresh/draft workflow. Its fixture now explicitly opens a physical Sort before exercising an automatic request. Suite totals overlap and should not be added together.

## Rollback and savings verification

The release needs no schema or data migration. Roll back the release commit through the established Render workflow, preserving any intervening changes. Response-size optimizations are negotiated and older open tabs can continue using the original protocol. Check health, a signed-in board, an unchanged and a changed state response, and physical-window enforcement after rollback.

Actual dollar savings are pending. At the marginal bandwidth rate observed in the audit, avoiding 5 GB of **billed** traffic would save approximately $0.75. SQL counts and raw HTML bytes are not billed CU-hours or measured public transfer. This release does not claim savings from the held worker experiment. Compare one complete unscheduled day and two comparable Sorts by active display-hours, missions, endpoint/status counts, compressed egress, Neon active minutes and CU-hours, worker deadlines and archive backlog. Attribute service-initiated transfer by destination class before making further cost changes.
